# Hashimon bestiary art — for the landing page

Real pixel art for the Lovable bestiary, generated from each Hashimon's DNA by
the same `HashimonSprite` compiler the game uses. Drop these into the landing so
the creature cards show art instead of text.

## What's here
- `creatures/<key>.png` — one 160×160 transparent sprite per species (13 total).
- `hashimon-bestiary.png` — all 13 on one 640×640 sheet (4 columns, 160px cells).
- `bestiary.json` — metadata + sheet coordinates for every creature.

## Using it in Lovable / React

**Simplest — individual images.** Upload the `creatures/` folder and map each
card by `key`:

```jsx
// bestiary.json → creatures[]
{creatures.map(c => (
  <div className="card" key={c.key}>
    <img src={`/creatures/${c.key}.png`} alt={c.name}
         style={{ imageRendering: "pixelated", width: 96, height: 96 }} />
    <h3>{c.name}</h3>
    <span>{c.type} · {c.subtype} · {"★".repeat(c.stars)}</span>
    <p>{c.description}</p>
  </div>
))}
```

**Or the sheet** — slice with `object-position` from `hashimon-bestiary.png`
using each creature's `sheet: {x,y,w,h}` in the manifest.

> `image-rendering: pixelated` is important — without it the browser blurs the
> pixel art when scaled.

## Keeping it in sync
These are regenerated by `node scripts/export_sprites.cjs` (the headless exporter). When
the species catalog or the sprite generator changes, re-run it and re-upload.
The sprite is a pure function of the DNA, so the art is stable and reproducible:
the same creature always renders the same, in the game and on the site.

## Note on "canonical" look
Each sheet sprite is the species' **canonical individual** (its base birth
nonce). In-game, every captured individual has its own DNA and therefore its own
unique colour/markings — these files are the representative "dex" portrait.
